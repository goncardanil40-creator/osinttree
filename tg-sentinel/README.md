## 📌 Что это и зачем

В Telegram встречаются боты и каналы, которые торгуют или публикуют **чужие персональные данные**: номера телефонов, адреса, паспорта, сливы баз данных, деанон. Это нарушает Telegram Terms of Service и законы о персональных данных.

**TG Sentinel** — это CLI-инструмент на базе [Telethon](https://docs.telethon.dev/), который помогает оформить и отправить **доказательную жалобу** через официальный MTProto от имени вашего пользовательского аккаунта:

- 🔎 находит в сообщениях цели персональные данные (почта, телефоны, паспорта, СНИЛС, ключевые слова доксинга);
- 💾 автоматически собирает **доказательства** (профиль + сообщения с ID и датами);
- 📨 подаёт жалобу официальными методами `account.reportPeer` и `messages.report` с причиной **«Разглашение персональных данных»**;
- 🧾 ведёт журнал, генерирует черновики писем в поддержку Telegram и форму GitHub, строит HTML-отчёт;
- 🛡 по умолчанию работает в режиме **dry-run** и защищает аккаунт от флуда и бана.

> ⚠️ Bot API Telegram **не содержит** методов жалобы вообще — жаловаться может только пользовательский аккаунт. Поэтому инструмент работает через user-сессию Telethon, а не через токен бота.

## ⚙️ Как это работает под капотом

| Метод MTProto | Назначение |
|---|---|
| `account.reportPeer` | Жалоба на бота/аккаунт/канал **целиком** + причина + комментарий модератору |
| `messages.report` | Жалоба на **конкретные сообщения** — доказательства (динамические категории современного API + легаси-режим) |
| `account.reportProfilePhoto` | Жалоба на аватар, если на нём чужие документы/лица |
| `contacts.block` | Блокировка нарушителя после жалобы |

Список причин — официальный конструктор `ReportReason`: `personal` (персональные данные), `spam`, `fake`, `violence`, `pornography`, `child_abuse`, `copyright`, `illegal_drugs`, `geo`, `other`.

## 🚀 Установка

### 1. Получите API-ключи Telegram

1. Зайдите на **<https://my.telegram.org>** под своим номером;
2. Откройте **API development tools**;
3. Создайте приложение — получите **`api_id`** (число) и **`api_hash`** (строка).

### 2. Установите инструмент

```bash
git clone https://github.com/goncardanil40-creator/osinttree.git
cd osinttree/tg-sentinel

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Настройте конфиг

```bash
cp config.example.json config.json
```

Впишите в `config.json` свои `api_id` и `api_hash`:

```json
{
  "api_id": 1234567,
  "api_hash": "abcdef0123456789abcdef0123456789",
  "daily_limit": 5,
  "max_flood_wait": 90,
  "evidence_limit": 50
}
```

| Параметр | Смысл |
|---|---|
| `daily_limit` | Максимум **живых** жалоб в сутки с одного аккаунта (защита от бана) |
| `max_flood_wait` | Сколько секунд ждать при FloodWait, прежде чем пометить цель как `flood` |
| `evidence_limit` | Сколько последних сообщений сканировать при сборе доказательств |

### 4. Войдите в аккаунт

```bash
python tg_sentinel.py login
```

Введите номер и код из Telegram (при включённой 2FA — облачный пароль). Сессия сохранится в папку `sessions/` и больше не потребует кода.

## 🧭 Полное руководство по командам

### 🔍 `check` — разведка цели (только чтение, ничего не отправляет)

```bash
python tg_sentinel.py check @doxx_bot
python tg_sentinel.py check https://t.me/doxx_bot --limit 100
```

Покажет досье (ID, username, тип, флаг бота) и найдёт сообщения с персональными данными. **Начните всегда с этой команды** — убедитесь, что цель действительно нарушает.

### 💾 `evidence` — сбор доказательств

```bash
python tg_sentinel.py evidence @doxx_bot
```

Создаёт в папке `evidence/` два файла: JSON (машиночитаемый) и TXT (читаемый протокол с ID сообщений, датами и подсвеченными находками PII).

### 📨 `report` — подача жалобы

```bash
# Безопасный прогон БЕЗ отправки (режим по умолчанию):
python tg_sentinel.py report @doxx_bot

# Явный dry-run с несколькими целями и своей причиной:
python tg_sentinel.py report @bot1 @bot2 --reason personal

# Пакетно по файлу целей:
python tg_sentinel.py report targets.example.json

# РЕАЛЬНАЯ отправка (потребует подтверждение словом ДА):
python tg_sentinel.py report @doxx_bot --live

# Жалоба + блокировка + жалоба на аватар, без вопроса:
python tg_sentinel.py report @doxx_bot --live --block --photo --yes
```

Флаги:

| Флаг | Действие |
|---|---|
| `--reason personal` | Причина жалобы (по умолчанию `personal` — персональные данные) |
| `--comment "текст"` | Свой комментарий модератору вместо автотекста |
| `--account main` | Имя сессии, если аккаунтов несколько |
| `--live` | Реальная отправка (без флага — сухой прогон) |
| `--block` | Заблокировать цель после жалобы |
| `--photo` | Дополнительно пожаловаться на аватар |
| `--yes` | Пропустить интерактивное подтверждение |

### ✍️ `draft` — черновики жалоб без отправки

```bash
python tg_sentinel.py draft @doxx_bot
```

Сгенерирует в `drafts/`:
- готовое **письмо на abuse@telegram.org** (на русском);
- готовый текст для **формы жалобы GitHub** (если утечка продублирована в репозитории).

Если вы заранее собрали доказательства (`evidence`), черновик автоматически подставит факты.

### 🚫 `block` — просто заблокировать

```bash
python tg_sentinel.py block @doxx_bot
```

### 📒 `ledger` — журнал жалоб

```bash
python tg_sentinel.py ledger
```

Покажет все отправленные жалобы, их статусы (`accepted`, `flood`, `rejected`, `error`), цели и аккаунты. Журнал не даёт отправить дубль жалобы и следит за суточным лимитом.

### 🌐 `html` — красивый HTML-отчёт

```bash
python tg_sentinel.py html report.html
```

Отчёт с водяным знаком `@loomaxer` — можно приложить к обращению в поддержку.

### 👥 `accounts` и 🧪 `selftest`

```bash
python tg_sentinel.py accounts     # список сохранённых сессий
python tg_sentinel.py selftest     # 24 офлайн-теста без сети и Telegram
```

## 📄 Формат файла целей

`targets.json` (шаблон — `targets.example.json`):

```json
{
  "targets": [
    {
      "target": "@example_doxx_bot",
      "reason": "personal",
      "comment": "Публикует чужие паспорта и телефоны без согласия — доксинг.",
      "message_ids": []
    },
    {
      "target": "https://t.me/example_sliv_channel",
      "reason": "personal",
      "comment": "",
      "message_ids": [101, 102, 105]
    }
  ]
}
```

- `target` — `@username`, ссылка `t.me/...` или числовой ID;
- `message_ids` — пустой массив означает «взять 5 самых явных сообщений с PII автоматически»;
- пустой `comment` — текст жалобы сгенерируется автоматически по собранным фактам.

## 🧯 Защита от бана и ошибок

1. **Dry-run по умолчанию** — без `--live` наружу не уходит ни одного запроса-жалобы.
2. **Суточный лимит** (`daily_limit`) — перед превышением инструмент остановится.
3. **Антидубль** — повторная жалоба на ту же цель с того же аккаунта пропускается.
4. **FloodWait** — короткие паузы Telegram переживаются с обратным отсчётом, длинные помечаются `flood` без риска для аккаунта.
5. **Анти-бот совместимость** — автоматический выбор динамических категорий (`option: bytes`) в новых версиях Telethon и легаси-режима (`reason`) в старых.
6. **Подтверждение** — live-режим требует ручного ввода слова `ДА`.

## ❓ Частые вопросы

**Это безопасно для моего аккаунта?**
Инструмент использует официальный клиентский API Telethon. Риски возникают только при злоупотреблении (ложные/массовые жалобы) — поэтому встроены лимиты и подтверждения. Не используйте основной аккаунт для экспериментов.

**Жалобы анонимны?**
Telegram не раскрывает заявителя нарушителю, но модерация видит, с какого аккаунта пришла жалоба.

**Можно ли жаловаться с нескольких аккаунтов?**
Технически да (`login <имя>` + `--account`), но накрутка жалоб является злоупотреблением и приводит к блокировке ваших аккаунтов. Подавайте одну честную жалобу с одного аккаунта.

**Сколько ждать рассмотрения?**
Зависит от загрузки модерации — обычно от нескольких часов до суток. Решение принимает живой модератор по содержанию нарушения, а не по количеству жалоб.
